# AI Finance Assistant

Multi-agent financial education assistant (LangGraph + RAG + Streamlit).

> Work in progress. Full README (architecture, setup, API docs, troubleshooting) is written on Day 13.

## Quick start
1. Create a virtual environment and install `requirements.txt`
2. Copy `.env.example` to `.env` and add your `GOOGLE_API_KEY`
3. Run `smoke_test.py`

## Running the app
In VS Code open **Run and Debug**, choose **AI Finance Assistant (Streamlit)** and press F5 (`.vscode/launch.json`), or run `streamlit run app.py` from the repo root. The app listens on `http://localhost:8501` only. The first start loads the search index and the embedding model, so it takes a while; the sidebar shows when it is ready. The chat sends your question through the same workflow as the tests; usage in the sidebar counts tokens for the whole running app (all visitors) and is cleared only by restarting the app, not by "New conversation". Tabs: **Chat** (any question), **Market** (tickers separated by commas, such as `AAPL` or `TCS.NS, INFY.NS`, and a period: price charts, comparison table and the data source with its time) and **News** (a topic such as `Nifty 50`, or a ticker: a short summary with links to the headlines it is based on).

## Company names and tickers
The Market tab and the Chat accept a ticker (`AAPL`, `TCS.NS`, `^NSEI`) or a company name (`Suzlon`, `Infosys`). The language model never supplies a ticker. A name becomes a symbol only through the alias table in `config.yaml` or a Yahoo search, and every symbol is price-checked before use (`src/data/tickers/`, settings in `ticker_lookup:`). If a name matches several listings the app lists them with exchange and currency and asks you to type the ticker; if the lookup is down it asks for the ticker instead of guessing. A trailing "exchange: code" such as `Infosys NSE: INFY` is dropped before matching (the code is never used as a ticker). A name that is not a real company, or one that is not found, gets a "couldn't find a listed company" answer.

**Known limitation:** the ticker format check (`validate_symbol` in `src/data/market/provider.py`) is a deliberate whitelist of US symbols, NSE `.NS` symbols and indexes. Companies listed only on the BSE (`.BO`) or only abroad (`.TW`, `.DE`, `.TO`, ...) cannot be price-checked, so they come back "not found". `.L` and `.F` pass only because the US rule allows a one-letter suffix (meant for share classes such as `BRK-B`). The planned fix is an explicit list of exchange suffixes in `config.yaml`, not a looser pattern.

## Live check transcripts
`docs/live_checks/` holds the real output of the `live_check_*.py` scripts, saved as `<script>-<YYYY-MM-DD>.txt` each time the author ran one against the real LLM and data sources. They are not generated by the tests. A transcript captures stdout only (what the script prints), not log lines. Redaction is limited: it removes the values of environment variables whose name contains KEY, TOKEN, SECRET or PASSWORD, `sk-...` keys, `Bearer` tokens and `Authorization:` lines, nothing else. **Read each transcript before committing it.** The four transcripts dated 2026-10-31 (`live_check_qa`, `live_check_router`, `live_check_tax`, `live_check_workflow`) were checked by the author for secret patterns, user name and e-mail addresses before they were committed.

## Technology choices

- **FAISS (not Pinecone or Chroma):** a local index file with no server or account, which is enough for 60 articles. It sits behind a `VectorStore` interface, so Chroma or Pinecone can be swapped in through config (architecture section 5).
- **yfinance (not Alpha Vantage):** free, no API key for quotes and history, covers US and NSE (`.NS`) tickers. Alpha Vantage is a later option behind the same provider interface (architecture section 6).
- **OpenAI model (`llm.provider: openai`, model set in `config.yaml`):** chosen by the project author, with the per-token prices in `config.yaml` used to track a limited budget. Gemini is also supported by `get_llm()`; changing provider or model is a config edit, not a code change.
- **Google News RSS (not yfinance news):** the yfinance news feed returned nothing in testing, and the RSS search feed also takes free phrases such as "Nifty 50". It needs no new dependency (standard library only).
- **Local sentence-transformers embeddings (`all-MiniLM-L6-v2`):** run on the local machine, so indexing and retrieval cost no API tokens and the RAG evaluation harness can run offline.

## RAG tuning results

The retrieval settings were chosen with the evaluation harness in `tests/rag_eval/` (run with `run_rag_eval.py`; it uses the local embedder, so it costs no API tokens). The harness uses the same `select_chunks()` function as the app, so it measures what the app does. Scores are the share of questions whose labelled article is in the top `top_k` (hit rate) and the mean reciprocal rank of the first correct article (MRR). The development set has 121 questions; the held-out set has 10 independent questions.

| chunk_size | chunk_overlap | top_k | threshold | dev hit rate | dev MRR | held-out hit rate | held-out MRR |
|---|---|---|---|---|---|---|---|
| **300** | **120** | **6** | **0.30** | **1.000** | **0.865** | **1.000** | **0.753** |
| 400 | 120 | 6 | 0.30 | 0.992 | 0.851 | 0.900 | 0.750 |
| 400 | 60 | 6 | 0.35 | 0.992 | 0.858 | 0.900 | 0.700 |

Each row was scored with the diversity caps on and off; the numbers were identical, so the table shows one value. No off-topic question matched anything in any row.

**Why 300 / 120 / 6 / 0.30 won:** it has the best hit rate and the best MRR on both the development set and the held-out set, and it lets through no more false matches than the others. A likely reason is that smaller chunks keep each chunk closer to one idea, but that was not tested separately. The settings are applied in `config.yaml` (glossary keeps its own 250/0 chunking).

**Held-out caveat:** ten questions is a small sample. One question is worth 0.10 of hit rate, so the held-out gap between 300/120 and the other two rows is a single question ("What happens to my money if the stock market crashes tomorrow?"). The held-out set also informed the final choice, so treat its scores as indicative, not a guarantee.

**Near-miss limitation:** the threshold does not separate finance-adjacent questions that the knowledge base does not cover (for example loans, crypto or insurance) from answerable ones: 4 of 5 such near-miss questions still retrieve something above 0.30 in every row. Measured with `run_rag_eval.py` on the app's retrieval path (row 300/120/6/0.30): the highest near-miss best-chunk score is 0.578 ("What is a credit score and how do I improve it?"), above the lowest answerable score of 0.321, so no threshold separates the two sets, and the 0.30 threshold lets 4 of the 5 near-miss questions through. The grounded prompt therefore provides the final refusal: retrieval can return chunks for a question the knowledge base does not cover, and the model must say so. Raising the threshold enough to stop this would also drop correct answers, so retrieval alone cannot solve it. The defence is layered: (1) a grounded prompt that tells the model to answer only from the retrieved context and to say so when the context does not cover the question, and (2) the router's `out_of_scope` intent, which sends questions outside the assistant's topics to a safe response before retrieval is used (architecture sections 3.3 and 4). These two layers belong to the agent and router steps and are not built yet.

## Finance Q&A results

The Finance Q&A agent rewrites a colloquial question into a plain finance query, retrieves with both versions, and answers from the cited context only. A 12-question live check on `gpt-6-luna` (`live_check_qa.py`, real index and real LLM) gave:

- **Answerable: 6 of 6** answered with valid citations. Two of these were colloquial questions that query rewriting rescued.
- **Not covered: 6 of 6** correctly returned `no_answer`: the 5 near-miss questions and 1 off-topic question. They passed retrieval, so the grounded prompt (reply `NO_ANSWER` when the context does not answer) is what stopped them. This is the layered defence described under "RAG tuning results".
- **Cost:** about $0.0015 for the 12 questions (roughly $0.00013 per question).
- **Latency:** about 27 seconds for the first call (cold start), then 3.5 to 9 seconds.

This is a small sample (12 questions), so treat it as a sanity check, not a benchmark.
